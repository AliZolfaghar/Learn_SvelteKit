# درس ۳: توضیح کامل فایل‌های پیکربندی پروژه

## هدف درس
بعد از این درس، شاگرد می‌تواند تک‌تک خطوط و بخش‌های مهم این فایل‌ها را توضیح دهد:
`package.json`، `vite.config.ts`، `tsconfig.json`، `.npmrc`، `.gitignore`، `src/app.d.ts` و `lessons/.gitkeep`.

## پیش‌نیاز
- درس ۱ و ۲
- داشتن پروژهٔ ساخته‌شده با `npx sv create`

## قدم ۱: فایل `package.json`

این فایل «شناسنامه و دفترچه دستورات» پروژه است.

### بخش هویت پروژه

```json
"name": "learn-sveltekit",
"private": true,
"version": "0.0.1",
"type": "module"
```

| کلید | معنی |
|------|------|
| `name` | نام پکیج/پروژه |
| `private: true` | این پروژه را تصادفی با `npm publish` منتشر نکن |
| `version` | نسخهٔ فعلی پروژه |
| `type: "module"` | فایل‌های JS به‌صورت ESM (`import`/`export`) تفسیر شوند |

### بخش `scripts`

```json
"scripts": {
  "dev": "vite dev",
  "build": "vite build",
  "preview": "vite preview",
  "prepare": "svelte-kit sync || echo ''",
  "check": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json",
  "check:watch": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json --watch"
}
```

| اسکریپت | کار |
|----------|-----|
| `npm run dev` | سرور توسعه را با Vite اجرا می‌کند |
| `npm run build` | نسخهٔ نهایی برای استقرار می‌سازد |
| `npm run preview` | خروجی build را محلی تست می‌کند |
| `prepare` | بعد از `npm install` اجرا می‌شود؛ `svelte-kit sync` تایپ‌ها/مسیرهای داخلی را هم‌تراز می‌کند. اگر شکست خورد، با `|| echo ''` نصب را خراب نمی‌کند |
| `check` | sync + بررسی تایپ و صحت Svelte |
| `check:watch` | همان بررسی، ولی در حالت watch (مدام) |

### بخش `devDependencies`

```json
"@sveltejs/adapter-auto": "^8.0.0",
"@sveltejs/kit": "^3.0.0",
"@sveltejs/vite-plugin-svelte": "^7.2.0",
"svelte": "^5.57.1",
"svelte-check": "^4.6.0",
"typescript": "^6.0.3",
"vite": "^8.3.0"
```

| پکیج | نقش |
|------|-----|
| `@sveltejs/kit` | خود فریمورک SvelteKit (نسخهٔ ۳) |
| `svelte` | کامپایلر/زبان کامپوننت (نسخهٔ ۵) |
| `vite` | ابزار build و dev server |
| `@sveltejs/vite-plugin-svelte` | اتصال Svelte به Vite |
| `@sveltejs/adapter-auto` | انتخاب خودکار نحوهٔ استقرار بر اساس محیط |
| `svelte-check` | بررسی استاتیک کد Svelte/TS |
| `typescript` | پشتیبانی TypeScript |

`^` یعنی نسخه‌های سازگار بالاتر در همان major اجازهٔ نصب دارند.

### بخش `imports` (alias جدید)

```json
"imports": {
  "#lib": "./src/lib/index.js",
  "#lib/*": "./src/lib/*"
}
```

| الگو | معنی |
|------|------|
| `#lib` | به `src/lib/index.js` اشاره می‌کند |
| `#lib/*` | هر مسیر زیر `src/lib/` |

این همان جایگزین مدرن `$lib` در SvelteKit 3 است. مثال:

```ts
import favicon from '#lib/assets/favicon.svg';
```

## قدم ۲: فایل `vite.config.ts`

این فایل به Vite می‌گوید چطور پروژه را اجرا و build کند؛ در SvelteKit 3 تنظیمات Kit هم همین‌جا می‌آید.

```ts
import adapter from '@sveltejs/adapter-auto';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';
```

- `adapter-auto`: adapter پیش‌فرض و هوشمند
- `sveltekit`: پلاگین رسمی Kit برای Vite
- `defineConfig`: کمک به تایپ و autocomplete تنظیمات Vite

```ts
export default defineConfig({
  plugins: [
    sveltekit({
      compilerOptions: {
        runes: ({ filename }) =>
          filename.split(/[/\\]/).includes('node_modules') ? undefined : true
      },
      adapter: adapter()
    })
  ]
});
```

### `runes`

در Svelte 5، **runes** مدل واکنشی جدید است (`$state`, `$props`, …).

این تابع می‌گوید:
- اگر فایل داخل `node_modules` باشد → دخالت نکن (`undefined`)
- اگر فایل متعلق به خود پروژه باشد → `runes: true` (اجبار حالت جدید)

یعنی کد خودت باید با سینتکس جدید Svelte 5 نوشته شود؛ کتابخانه‌های قدیمی‌تر مجبور نمی‌شوند.

### `adapter: adapter()`

Adapter مشخص می‌کند خروجی نهایی برای کجا آماده شود (Vercel، Node، Cloudflare و …).  
`adapter-auto` سعی می‌کند محیط را تشخیص دهد. اگر محیط خاصی داری، بعداً adapter مخصوص همان محیط را جایگزین می‌کنی.

## قدم ۳: فایل `tsconfig.json`

```json
{
  "extends": "$app/tsconfig",
  "compilerOptions": {
    "strict": true
  },
  "include": ["src", "vite.config.ts"]
}
```

| بخش | معنی |
|------|------|
| `extends: "$app/tsconfig"` | تنظیمات پایهٔ TypeScript که SvelteKit فراهم می‌کند را ارث ببر |
| `strict: true` | سخت‌گیری تایپ‌ها روشن باشد (خطاهای بیشتری زودتر دیده می‌شوند) |
| `include` | فقط `src` و `vite.config.ts` را برای چک کردن در نظر بگیر |

نکتهٔ آموزشی: لازم نیست همهٔ گزینه‌های پیچیده را خودت بنویسی؛ Kit پایه را می‌دهد و تو فقط چیزهای لازم را override می‌کنی.

## قدم ۴: فایل `.npmrc`

محتوا:

```text
engine-strict=true
```

یعنی اگر در `package.json` بخش `engines` تعریف شده باشد و نسخهٔ Node/npm سیستم با آن جور نباشد، npm نصب را سخت‌گیرانه‌تر متوقف یا رد می‌کند.

هدف: جلوگیری از اجرای پروژه با نسخهٔ ناسازگار Node روی سیستم شاگرد یا CI.

## قدم ۵: فایل `.gitignore`

این فایل به Git می‌گوید چه چیزهایی را commit نکند.

```gitignore
node_modules
```

وابستگی‌های نصب‌شده خیلی بزرگ‌اند و از روی `package.json` / `package-lock.json` دوباره ساخته می‌شوند.

```gitignore
.output
.vercel
.netlify
.wrangler
/.svelte-kit
/build
```

خروجی‌های build و tooling و پوشه‌های استقرار موقت.

| مسیر | معمولاً چیست؟ |
|------|----------------|
| `.svelte-kit` | فایل‌های تولیدشده توسط tooling داخلی Kit |
| `build` / `.output` | خروجی build |
| `.vercel` / `.netlify` / `.wrangler` | فایل‌های موقت پلتفرم‌های استقرار |

```gitignore
.DS_Store
Thumbs.db
```

فایل‌های سیستمی macOS و Windows که به پروژه ربطی ندارند.

```gitignore
.env
.env.*
!.env.example
!.env.test
```

- همهٔ فایل‌های محیطی (ممکن است کلید/رمز داشته باشند) نادیده گرفته شوند
- ولی `.env.example` و `.env.test` استثنا هستند تا نمونه‌ها در ریپو بمانند

```gitignore
vite.config.js.timestamp-*
vite.config.ts.timestamp-*
```

فایل‌های موقت timestamp مربوط به Vite را وارد Git نکن.

## قدم ۶: فایل `src/app.d.ts`

```ts
declare global {
  namespace App {
    // interface Error {}
    // interface Locals {}
    // interface PageData {}
    // interface PageState {}
    // interface Platform {}
  }
}

export {};
```

این فایل برای **تایپ‌های سراسری اپ** است.

| اینترفیس (فعلاً کامنت) | کاربرد آینده |
|-------------------------|--------------|
| `Error` | شکل آبجکت خطا در صفحات error |
| `Locals` | داده‌ای که روی `event.locals` در سرور می‌گذاری (مثل user) |
| `PageData` | شکل دادهٔ صفحات |
| `PageState` | state سمت کلاینت برای navigation |
| `Platform` | تایپ‌های مخصوص پلتفرم استقرار (مثل Cloudflare) |

`declare global` یعنی این namespace در کل پروژه دیده شود.  
`export {}` فایل را به یک module تبدیل می‌کند تا `declare global` درست کار کند.

الان همه کامنت‌اند؛ یعنی هنوز سفارشی‌سازی نکرده‌ایم. وقتی درس auth یا load برسد، اینجا زنده می‌شود.

## قدم ۷: فایل `lessons/.gitkeep`

این فایل **خالی** است و جزء SvelteKit نیست.

چرا وجود دارد؟
- Git معمولاً فولدر خالی را ذخیره نمی‌کند
- با گذاشتن `.gitkeep`، فولدر `lessons/` در ریپو می‌ماند حتی اگر هنوز درسی داخلش نباشد

پس نقشش فقط «نگه‌داشتن فولدر در Git» است، نه اجرای برنامه.

## جمع‌بندی

| فایل | یک جمله |
|------|---------|
| `package.json` | نام، اسکریپت‌ها، پکیج‌ها و alias `#lib` |
| `vite.config.ts` | اتصال Vite + SvelteKit + adapter و اجبار runes |
| `tsconfig.json` | تنظیم TypeScript روی حالت سخت‌گیرانه |
| `.npmrc` | سخت‌گیری روی engine/نسخهٔ محیط |
| `.gitignore` | چه چیزهایی وارد Git نشوند |
| `src/app.d.ts` | محل تعریف تایپ‌های سراسری App |
| `lessons/.gitkeep` | نگه داشتن فولدر خالی درس‌ها در Git |

## تمرین
1. فرق `npm run dev` و `npm run preview` را با یک مثال واقعی بنویس.
2. توضیح بده چرا `node_modules` و `.env` در `.gitignore` هستند.
3. بگو `#lib` در `package.json` به کدام مسیر واقعی اشاره می‌کند.
4. یکی از اینترفیس‌های داخل `app.d.ts` را انتخاب کن و حدس بزن در چه سناریویی uncomment می‌شود.
